# `app-shell.mjs` re-finds client bundles by their rendered text, so changing a call signature can silently un-inject one

**Why it mattered:** Release 3 changed one call from `partnersHomeBrowserSource()` to
`partnersHomeBrowserSource(options)` so the flag could gate what ships. That silently
removed the **social production controller** from every page whenever
`FOUNDER_OS_RELATIONSHIPS` was on. Nothing failed. No test caught it. The only signal was
the client-JavaScript measurement reporting the flag-on build as 6,907 bytes *smaller* than
the flag-off build, which an additive change cannot be.

`renderVNextDesktopShell` injects the client bundles with one big
`html.replace("</body>", ...)`. Some bundles are then inserted by a **second** replace that
anchors on the rendered text of a bundle already in the document:

```js
if (options.socialEnabled) {
  html = html.replace(
    `<script>${partnersHomeBrowserSource(options)}</script>`,        // the anchor
    `<script>${socialProductionControllerBrowserSource()}</script>\n<script>${partnersHomeBrowserSource(options)}</script>`
  );
}
```

The anchor is not a marker — it is the entire serialized bundle, regenerated by calling the
same function again. If the two calls are not given **identical arguments**, they render
different text, the anchor is not found, and `String.replace` does what it always does when
there is no match: returns the string unchanged, with no error.

**How to apply:**

- Any time you change how a `*BrowserSource()` function is called in `app-shell.mjs`, grep
  for every other call to the same function in that file and change them together.
- Treat a byte count that moves the wrong way as a bug report, not a rounding artefact.
  Measure the client-JavaScript budget with the flag off **and** on for every release; the
  direction of the change is as informative as the size.
- A better shape, if this bites a third time: inject a stable comment marker
  (`<!--le:partners-home-->`) and anchor the second replace on that instead of on
  regenerated source.
